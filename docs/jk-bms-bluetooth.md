# JK BMS 藍牙接入

## 中文告警說明

已對目前支援版本的 JK02_24S 16-bit 告警字加入中文對照，保留 `alarm_raw`，新增 `alarm`（格式、原始十六進位、各位元訊息、未知位元及是否有告警）。UI 可同時列出多個訊息，有告警或未知位元時以橘色提示。零值只表示「此採樣未回報告警」，不是持續監看結果。

對照事實核對自 <https://github.com/syssi/esphome-jk-bms/blob/main/components/jk_bms_ble/__init__.py> 的 `DEFAULT_ERRORS_JK02`，與 reader 中 offset 136 的 16-bit 讀取對應。bit 4 是「電池已充滿」狀態，不當作過壓故障；bit 3 來源保留空白，顯示未知，不套用舊的電流感測器解釋。多位元全部保留；不支援的位寬不擅自截斷。

中文解碼跟隨每筆新快照保存，舊紀錄不改寫，若缺少解碼仍顯示原始碼。非零告警以合成協定資料測試，沒有刻意對電池製造過流、短路、過壓或溫度故障。

## 定時快照

頁面可明確選擇 15/30/60 秒間隔開始。首次立即讀取，之後每次完成讀取/保存後才計時，不重疊查詢。每次 BLE 讀完斷線，讀取或保存失敗時停止，不自動反覆重試；確認裝置後可手動重新開始。頁面離開即停止排程，不建立背景常駐服務。停止按鈕取消未來讀取；已送出的查詢仍需完成或逾時清理，畫面會明確顯示。

開始前及每次讀取前確認頁面已取得服務狀態、目標已登記、沒有 ESP32 自動測試及通訊錯誤。排程期間停用掃描/切換目標/手動重複讀取；服務端仍沿用已核對的兩個查詢指令與操作互斥。畫面採樣時間代表最後一次快照，不將等候間隔顯示成持續連線。瀏覽器背景節流可能延後計時，不保證固定時刻採樣。

已實機驗證 15 秒間隔連續讀取及逐次保存；停止時尚在途中的讀取完成後斷線，再等待超過 15 秒，紀錄沒有繼續增加。另有 5 項排程測試，涵蓋停止、在途完成、不重疊、失敗停止、狀態變更及計時器建立失敗。

## 快照保存與匯出

每次 `POST /api/bms/read` 成功後自動保存至忽略的 `pc/local/bms_snapshots/`，每份使用獨立識別與 SHA-256 完整性資料，不覆寫既有快照。讀取失敗不另存舊快照；保存失敗與 BLE 讀取成功分開回報。歷史資料包含原採樣時間、明確 BMS 位址與 PC 程式版本資訊；不是目前狀態，也不自動連線。

控制台可列出歷史時間、總壓及串數，下載完整 JSON 或每串 CSV。CSV 一行代表一串，含 UTC 採樣時間、位址、總壓/電流/SOC、電芯電壓（V）與均衡線電阻（Ω），採 UTF-8 BOM 供試算表開啟。容量交叉核對及原始告警解碼的限制另記於 JSON `field_notes`。

`GET /api/bms/snapshots` 列清單；`GET /api/bms/snapshots/<id>.json` / `.csv` 下載資料。固定根目錄、嚴格識別格式、檔案大小與完整性檢查；破損檔會略過並顯示計數。SHA-256 用於偵測檔案變化，並非來源數位簽章。檔案只存本機，不進 Git；整合測試 ZIP 已納入目前登記 BMS 的最新有效歷史快照（JSON 與每串 CSV），不會重新連線讀取，也不選用其他電池的資料；保留採樣時間，不代表同一次 HIL 測試。

`POST /api/bms/read` 不接受位址或指令參數，僅用本機登記目標；自動模型流程期間拒絕。掃描與讀取互斥，讀取中禁止切換目標，耗時查詢不持有模型通訊鎖。快照只在記憶體保存，開發驗證資料放忽略的 `pc/local/`。失敗保留舊快照並顯示錯誤，切換目標會清除舊資料。

## 已完成：掃描與本機登記

使用者指定藍牙介面。購買截圖顯示 8–17 串、0.6A 均衡、60A 持續的選項，表格可能對應 JK-BD6A17S6P；照片不是板身標籤，型號與硬/軟體版本仍待確認。訂單、姓名、地址及電話不納入程式或測試資料。

PC 使用 Bleak 3.0.2，主動掃描 BLE 廣播 5 秒（可能包含 scan request/response），不建立 GATT 連線、不配對、不讀寫 characteristic、不發送 JK 設定或充放電指令。Windows 實測掃描成功。名稱含 JK / JIKONG 僅為排序提示，不代表確定是極空保護板。

控制台「電池 BMS」快速導覽可開啟電池工作台。選擇明確位址後按「登記這塊保護板」；只接受 60 秒內掃描到的唯一位址，不自動選第一台。登記存於忽略的 `pc/local/jk_bms.json`，服務重啟後不自動連線。鄰近裝置清單只放記憶體，不進 Git 或整合資料包。掃描失敗會明確顯示，不當作成功的空清單。

API：`GET /api/bms/state`、`POST /api/bms/scan`、`POST /api/bms/select`（JSON `address`）。掃描與登記在模型自動測試期間拒絕，耗時掃描不持有模型通訊鎖。

初始未讀取時 `connected=false`、`protocol_verified=false`、`telemetry=null`；成功查詢後提供帶時間的實測快照。沒有電壓、電流或 SOC 的虛構數值。BMS 尚未列入既有 HIL 8 項計分，也不把廣播出現當成實機整合成功。
