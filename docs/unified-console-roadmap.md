# 統一控制台整合順序

## 已完成：裝置管理基礎

- 模擬電機、Gateway、原作者 ESP32 板分別登記角色；後者用途尚未確認。
- 以 USB VID/PID/序號識別，追蹤 COM 變動；識別不足或重複明確顯示。
- 串口掃描不開啟裝置。角色設定保存本機，不加入 Git。
- 可按登記角色連接模擬器；其他角色不從模擬器入口送指令。
- STM8/ST-Link、Android 保留獨立模組位置，尚未假裝具備操作能力。

## 已完成：自訂騎乘流程（ESP32 模型）

已可編排模型設定、路段持續時間、煞車及結尾停止，保存/載入 PC 計畫；沿用互斥執行、通訊監測、中止清理、版本紀錄與完整報告。已在 ESP32 實測三路段與停止，以及中止流程。流程內故障刺激與其他裝置動作待後續擴充。

## 已完成：Android 接入基礎

已找到 PC 現有 Android SDK ADB，可偵測清單、授權/離線狀態並登記唯一測試目標，不自動選第一支手機。尚未偵測到實體手機；App 啟動、截圖與紀錄仍待後續接入。未改動手機設定或安裝 App。

## 後續接入

1. Android：確認官方 ADB 工具與實體測試手機，先偵測、啟動指定 App、截圖及收集紀錄。App 套件名與測試流程待確認。
2. STM8：確認實際控制板、ST-Link、韌體來源、編譯與燒錄工具，再提供受限的目標操作。SWIM 接線不推測。
3. Gateway / 原作者 ESP32 板：確認板型、來源專案與串口用途；若不是同一塊板，維持兩個角色。
4. 跨裝置流程：每一步指定裝置角色，裝置不符或未接入即停止，集中保存各端紀錄。
5. DAC 到貨：核對完整型號與供電，配置確認後的 GPIO，先量測與校正，再開放實體非零輸出。

目前遠端使用延續既有 PC / Codex 方式，服務仍只監聽 127.0.0.1，不擴大對外網路存取。
