# 統一控制台整合順序

## 已完成：裝置管理基礎

- 模擬電機、Gateway、原作者 ESP32 板分別登記角色；後者用途尚未確認。
- 以 USB VID/PID/序號識別，追蹤 COM 變動；識別不足或重複明確顯示。
- 串口掃描不開啟裝置。角色設定保存本機，不加入 Git。
- 可按登記角色連接模擬器；其他角色不從模擬器入口送指令。
- STM8/ST-Link、Android 保留獨立模組位置，尚未假裝具備操作能力。

## 已完成：自訂騎乘流程（ESP32 模型）

已可編排模型設定、路段持續時間、煞車及結尾停止，保存/載入 PC 計畫；沿用互斥執行、通訊監測、中止清理、版本紀錄與完整報告。已在 ESP32 實測三路段與停止，以及中止流程。流程內故障刺激與其他裝置動作待後續擴充。

## 已完成：Android 接入基礎

已核對原作者 Android Manifest，加入已指定測試手機的固定 App 啟動操作及安裝存在檢查。缺手機、未授權或未安裝時明確拒絕；不自動安裝或授權。尚無實體手機，成功路徑僅以測試替身驗證，BLE 未驗證。

已找到 PC 現有 Android SDK ADB，可偵測清單、授權/離線狀態並登記唯一測試目標，不自動選第一支手機。尚未偵測到實體手機。已加入指定手機截圖與本機紀錄，成功路徑以測試替身驗證、實機待驗證；App 啟動待實機驗證，跨裝置流程仍待後續接入。未改動手機設定或安裝 App。

## 已完成：STM8 工作台準備檢查

可手動列舉 Windows ST-Link 名稱或 ST USB 候選裝置、驅動狀態，查找 SDCC/STVP/stm8flash，並在本機登記 GitHub 韌體來源。只做環境檢查，未啟用編譯、SWIM 存取或燒錄。候選 USB 裝置不等於已驗證 STM8 目標。工具版本與專案來源仍待確認。

## 後續接入

JK02_24S 中文告警對照已加入快照與畫面，保留原碼、未知位元與「充滿」狀態區別；非零告警用合成封包驗證，不製造實體電池故障。

已加入頁面定時 BMS 快照：15/30/60 秒完成後間隔、逐次保存、停止排程及失敗即停止。非持續 BLE 連線，未建立背景自動重連服務。

BMS 成功單次讀取後已可自動保存本機歷史，匯出完整 JSON 及每串 CSV，保留採樣時間與校驗資料；失敗不另存舊快照。與模型報告仍分開，尚未宣稱同步 HIL 驗證。

JK BMS 已進一步完成指定板 HW10.XW/SW10.07 的單次查詢及 PC 數據顯示，實測 13 串、約 45.6V。只有裝置/狀態兩個查詢，讀取後斷線；不是常駐即時連線，沒有充放電控制或設定修改。

JK BMS 藍牙接入：已實作 PC BLE 掃描、名稱候選提示、明確位址登記及指定版本單次狀態讀取。階段與來源見 [JK BMS 藍牙接入](jk-bms-bluetooth.md)。此工作不依賴 DAC 到貨。

控制台已加入 8 個工作區快速導覽與置頂停止模型按鈕；手機窄版逐項跳轉及實機 STOP 已驗證。停止按鈕沿用既有流程，不新增控制協定。

已加入整合準備總覽與 JSON 匯出，彙整模型通訊/停止、STM8 產物和手機授權快照。Gateway 通訊、SWIM、DAC 與真 BLE 維持待驗證，完整 HIL 不因裝置登記或離線編譯而變為就緒。

已加入整合測試 ZIP 資料包：準備快照、最近有效已保存模型報告、通過檔案校驗的 STM8 編譯報告、目前登記 BMS 的最新有效歷史快照（JSON／每串 CSV）與 SHA-256 清單。BMS 匯出不重新連線、不選其他電池，保留原採樣時間。缺項及不同測試時間/範圍會明確記錄，未宣稱跨裝置回歸已完成。

已完成 STM8 固定版本離線編譯；流程與實測雜湊見 [STM8 離線編譯](stm8-offline-build.md)。使用 SDCC 4.4.0，兩次獨立編譯 HEX 一致；保留 19 行上游警告。控制台可偵測 PlatformIO 安裝的 SDCC；目前仍不提供 STM8 燒錄操作。

控制台已可檢視本機保存的離線編譯版本、HEX 雜湊與資料範圍、警告及下載 JSON 報告。每次讀取重新檢查韌體檔；來源不符及缺檔/校驗失敗會明確提示，不等於實體板驗證。

### STM8 來源核對（2026-10-24）

使用者指定的[控制器燒錄指南](https://github.com/TSDZ2-ESP32/TSDZ2-ESP32-Wiki/wiki/TSDZ-Controller-Flash)對應 STM8 控制器。指南連到 Wiki repository 的 `bin/STM8` 成品目錄；查詢時包含 `TSDZ2-v16.zip`，尚未下載或驗證其內容及相容性。

同組織的[控制器原始碼](https://github.com/TSDZ2-ESP32/TSDZ2-Smart-EBike) README 明確說明為 TSDZ2 馬達控制器韌體，已登記到本機工作台。`src/compile.bat` 使用 SDCC 和 make，`src/Makefile_windows` 指定 STM8，產生 `main.ihx`；`release.bat` 將其複製為版本化 `.hex`。尚未確認可重現編譯所需的 SDCC 版本，也未證實原始碼與任何成品版本逐位元相符。

指南另有為 Android OTA 啟用 bootloader 的 Option Byte 寫入步驟；這是獨立的控制器設定變更，未自動執行。待確認板型、備份與 SWIM 接線後再規劃。原作者 ESP32 板及 ESP32-S3 模擬器仍維持不同角色。

1. Android：確認官方 ADB 工具與實體測試手機，完成指定 App 啟動、截圖與真 BLE 的實機回歸。App 套件名與測試流程待確認。
2. STM8：確認實際控制板、ST-Link、韌體來源、編譯與燒錄工具，再提供受限的目標操作。SWIM 接線不推測。
3. Gateway / 原作者 ESP32 板：確認板型、來源專案與串口用途；若不是同一塊板，維持兩個角色。
4. 跨裝置流程：每一步指定裝置角色，裝置不符或未接入即停止，集中保存各端紀錄。
5. DAC 到貨：核對完整型號與供電，配置確認後的 GPIO，先量測與校正，再開放實體非零輸出。

目前遠端使用延續既有 PC / Codex 方式，服務仍只監聽 127.0.0.1，不擴大對外網路存取。
